# DisDown website

A complete static product website for DisDown. The deployable directory is `dist/`; there is no build step or production dependency. All interactions run in the browser. The page never connects a Discord account, accepts credentials, or sends archive content anywhere.

## Local preview

From this directory, use `npm run preview` and open `http://127.0.0.1:4178`. Set `DISDOWN_SITE_PORT` to choose another port. The local server only serves `dist/`, so development notes and app files stay outside the web root.

## Contents

- Editorial product narrative with original DisDown branding and real sample-workspace screenshots.
- Light, Dark, and Blurple Twilight website themes; the main screenshot follows the selected theme. Browser preference supplies the first visit, and browser-local storage remembers the choice.
- Accessible keyboard format tabs, actual sample output, individual format downloads, and a sampler ZIP containing all five standalone formats.
- Download links for all eight v0.2.0 release packages, installation guidance, account-risk and access-limit information, FAQ, public source, security, and support links.
- Original-logo social image, self-hosted Noto Sans, responsive layouts, reduced-motion support, and no analytics or external font service.

## Verification

`npm run check` checks JavaScript syntax, public-origin metadata, local assets and anchors, unique ids, and required decision copy. `node scripts/verify-browser.mjs --capture` runs the browser checks and captures the six theme/viewport combinations. Set `DISDOWN_SITE_URL` to test a hosted origin; it defaults to `http://127.0.0.1:4178`. Set `DISDOWN_BROWSER_EXECUTABLE` to choose a browser binary; otherwise the script uses an available Playwright Chromium or local Chrome installation. Browser checks use the parent app's existing Playwright package. See `.impeccable/review/browser-verification.json` for the recorded results.

The source has no production package-install requirement. `scripts/prepare-assets.mjs` is a development-only asset refresh that uses the parent repository's existing `sharp`, `esbuild`, and `archiver` dependencies. It reads only the original branding, fabricated sample workspace, exporter, screenshot fixtures, and font package. It does not connect a Discord account or read live archive data. After replacing screenshots, restore their provenance records with Impeccable before shipping.

## Provenance and examples

The app screenshots originate in the parent `docs/screenshots/` directory and are encoded as WebP at their original dimensions. Each has an Impeccable provenance sidecar. The social image is the original DisDown logo on a charcoal field, supplied by the parent task. Fonts retain their bundled license in `dist/assets/fonts/LICENSE.txt`.

The five example files were generated by the app's actual `serialize` function using two fabricated messages from `src/shared/demo.ts`, with an explicit sample-data notice. The website sampler ZIP is a comparison download containing all five standalone formats; it is not a representation of the app's own ZIP bundle structure. No real Discord content, identities, private exports, or user statistics appear on the website.

## Cloudflare Workers hosting

The website deploys directly to Cloudflare Workers Static Assets from `dist/`. `wrangler.jsonc` uses the worker name `disdown`, enables its `workers.dev` address, and serves the existing `404.html` for missing paths. There is no Worker application code, database, runtime secret, or account integration. Wrangler is pinned to `4.148.0`; install the deployment tooling with `npm ci` in this directory.

Use `npm run dev` for the Workers local preview at `http://127.0.0.1:8787`. `npm run deploy:dry-run` checks the static source and prepares the deployment without publishing it. After authenticating Wrangler to the intended Cloudflare account, `npm run deploy` publishes the assets directly. The account identity and credentials remain outside the public configuration.

The public website is [disdown.timur-radjabov1.workers.dev](https://disdown.timur-radjabov1.workers.dev). The initial deployment was verified on October 29, 2026: all 27 deployed static files matched the local bytes, the custom 404 returned HTTP 404, and all 53 browser checks passed against the public URL.

The origin is recorded in `site.config.json`. Run `npm run set-origin -- https://your-final-domain.example` when changing it; this updates the canonical URL, Open Graph URL/image, and Twitter image together. To check a deployed website, run `DISDOWN_SITE_URL=https://your-domain.example node scripts/verify-browser.mjs`.

See Cloudflare’s [Static Assets documentation](https://developers.cloudflare.com/workers/static-assets/) and [custom 404 routing](https://developers.cloudflare.com/workers/static-assets/routing/static-site-generation/) for the hosting contract.
